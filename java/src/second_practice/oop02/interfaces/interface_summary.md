# Конспект: Интерфейсы (`interface`) в Java

**Пакет проекта:** `second_practice.oop02.interfaces` (практический блок `oop08/interfaces`)

## 1. Основные понятия

* **Интерфейс (`interface`)** — это контракт, определяющий набор методов, которые класс обязался реализовать. Он задает *поведение* ("что класс умеет делать"), а не его сущность.
* По умолчанию все методы без тела в интерфейсе являются `public abstract`, а поля — `public static final` (константами).

## 2. Ключевые возможности

* **Множественная реализация:** Класс в Java может реализовывать несколько интерфейсов одновременно (`implements Flyable, Swimmable`), обойдя ограничение одиночного наследования классов.
* **Наследование интерфейсов:** Интерфейс может наследоваться от других интерфейсов через ключевое слово `extends`.
* **Дефолтные методы (`default`):** Начиная с Java 8, методы могут иметь базовую реализацию прямо в интерфейсе, что позволяет расширять контракты без поломки существующего кода.

## 3. Сравнение: Абстрактный класс vs Интерфейс

| Критерий | Абстрактный класс (`abstract class`) | Интерфейс (`interface`) |
| :--- | :--- | :--- |
| **Отношение** | *"IS-A"* (Является чем-то) | *"CAN-DO"* (Способен делать) |
| **Наследование** | Одиночное (`extends`) | Множественное (`implements`) |
| **Поля** | Любые (обычные, private, static и т.д.) | Только константы (`public static final`) |
| **Конструктор** | Есть (для вызова через `super`) | Отсутствует |

## 4. Разбор практических решений

### 1. Летающие и плавающие объекты (`Flyable.java`, `Swimmable.java`, `Duck.java`, `DuckMain.java`)
* Продемонстрирована множественная реализация интерфейсов: класс `Duck` реализует сразу два контракта — `Flyable` и `Swimmable`.

### 2. Устройства с дефолтными методами (`Powerable.java`, `SmartTV.java`, `DeviceMain.java`)
* Использован дефолтный метод `default void checkStatus()`, вызваный напрямую у экземпляра `SmartTV` без необходимости его переопределения.

### 3. Игровая система отрисовки (`Renderable.java`, `GameObject.java`, `Player.java`, `Item.java`, `GameWorldMain.java`)
* Реализовано сочетание абстрактного класса и интерфейса: `GameObject` хранит координаты `x` и `y`, а `Renderable` задает метод `render()`.
* В `GameWorldMain` продемонстрирован полиморфизм при работе с массивом `Renderable[]`.
