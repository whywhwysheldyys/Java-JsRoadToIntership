# Итоговый конспект: Методы в Java (`methods`)

**Пакет проекта:** `second_practice.basics01.methods`

---

## 1. Теоретические основы

* **Что такое метод?**
  Метод — это законченный блок кода, выполняющий определенную функцию, имеющий имя и переиспользуемый в других частях программы (соблюдение принципа **DRY** — *Don't Repeat Yourself*).

* **Структура объявления метода (сигнатура):**
  ```
  [модификаторы] <тип_возвращаемого_значения> <имя_метода>(<параметры>) {
      // тело метода
      return значение; // если тип не void
  }
  ```
  * **Сигнатура метода:** Имя метода + количество и типы его параметров.
  * **Параметры vs Аргументы:**
    * **Параметры** — переменные, объявленные в сигнатуре метода (сигнатура/шаблон).
    * **Аргументы** — конкретные значения, передаваемые в метод при его вызове.

* **Типы возвращаемых значений:**
  * Определяют, какой тип данных вернет метод после работы.
  * Ключевое слово **`void`** указывает, что метод **ничего не возвращает**.
  * Ключевое слово **`return`** используется для возврата значения или досрочного завершения выполнения метода (включая методы с типом `void`).

## 2. Перегрузка методов (Method Overloading)

**Перегрузка методов** — это возможность объявлять в одном классе несколько методов с одинаковым именем, но с разной сигнатурой (разным количеством или типами параметров).

### Правила перегрузки:
* Методы **обязаны** отличаться типами, порядком или количеством параметров.
* Изменение *только* типа возвращаемого значения **не является** перегрузкой и вызовет ошибку компиляции.

---

## 3. Способ передачи параметров (Pass-By-Value)

В Java параметры передаются **исключительно по значению (Pass-by-Value)**:
1. **Примитивные типы (`int`, `double` и др.):** В метод передается копия самого значения. Изменение внутри метода не влияет на исходную переменную.
2. **Ссылочные типы (массивы, объекты):** В метод передается копия *значения ссылки* (адреса ячейки памяти).
   * Изменение элементов/полей по ссылке изменит исходный объект.
   * Присвоение самой ссылке нового объекта внутри метода (`arr = new int[]{...}`) **не изменит** исходную ссылку снаружи.

## 4. Разбор практических решений

### 1. Перегрузка методов (`Calculator.java`)
Пример использования сигнатур с одинаковым именем `add` для работы с разным набором аргументов (`int`, `double`, `int[]`).
* Подсчет элементов массива через цикл `for`.
* Разделение логики: класс-утилита `Calculator` и класс для запуска `CalculatorMain`.

### 2. Валидация и работа со строками (`StringUtils.java`)
* Проверка на палиндром с использованием разворота строки через `new StringBuilder(str).reverse().toString()`.
* Корректное сравнение строк с помощью метода `.equals()`.
* Возврат значений (`boolean`, `String`) из методов вместо прямого вывода в консоль, что делает их универсальными.

### 3. Утилиты для массивов (`ArrayUtils.java`)
* Поиск максимума в массиве за один проход (`findMax`).
* Вывод массива с помощью утилиты `Arrays.toString()`.
* Реверс массива на месте (**In-place reverse**) с помощью алгоритма двух указателей без создания нового массива.

## 5. Мостик к ООП (Static vs Instance методы)

* **`static` методы:** Принадлежат самому классу. Вызываются через имя класса (`Calculator.add(...)`). Не требуют создания экземпляра через `new`.
* **Обычные (instance) методы:** Принадлежат объекту (экземпляру класса). Вызываются только у конкретного объекта, созданного через `new` (`Calculator calc = new Calculator(); calc.add(...)`).
